Why a right-click menu

The row already carries everything Claude needs — customer, area, product, SKU, the book it came from. Flagging at the row captures all of it automatically; nobody re-types context into a to-do. The menu also gives the row a home for other actions that currently hide in hover icons.

Touch fallback

Right-click doesn't exist on the iPad at the counter — the same menu opens from the ⋯ button at the row end (and could long-press). One menu, two doors.

The note is optional

A flag with no note still lands with full context. The quick-reason chips cover the common cases in one tap; the text box is for anything else.

The existing Issues & To-Do modal grows a second tab. Team list stays exactly as it is; flags from anywhere land on the Claude tab.

Issues & To-Do

Anything flagged for Claude — from a job line, a price book, or typed here — collects on this list. When you're ready to work them, Copy report builds one paste-ready markdown report with every open issue's note and captured data.

Shared with the whole team — unchanged. Bugs, ideas and shop reminders live here; things meant for a Claude session live on the Claude tab.

Source chip = way back

Every issue wears where it came from. Clicking a job line chip would open that customer at that row; a price book chip opens the book filtered to the SKU. The bucket is a launchpad, not a dead end.

One report, all sources

The per-book "Copy report" already proved the pattern — this is the same report across the whole bucket: each issue's note, its flags, and its full stored row data, grouped by source. One paste starts the Claude session.

Done, not deleted

Same rhythm as the team list — worked issues strike through and drop below, so "what did Claude fix last week" stays answerable until you clear them.

The same "Flag for Claude" popover is one shared component — every surface just hands it its own context.

Price book — the ✳ you already have

The button stays on every book row, but now it opens the same popover (note optional) and lands in the central bucket instead of a per-book one. The book page keeps its Claude filter chip — it just reads the shared list filtered to this book. Try it:

Sidebar — one door in

The Issues button badge splits: team count in ink, Claude count in clay. Opening it lands on whichever tab has news.

Anywhere else

The menu item + popover are shared, so any surface can grow a flag point later with one line: right-click a book table row, a search hit that returned the wrong thing, a version row, a vendor sheet. Each hands over its own context; the bucket doesn't care where a flag was born.

Data-wise this is its own small table (like todos), one row per flag with a source jsonb — the existing per-book claudeIssue marks migrate in as book-source rows.
