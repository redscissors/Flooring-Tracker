Project numbers — prototype

Every named project gets a permanent number — N100, then N101, N102… A project is born unnumbered; the number is stamped the first time a name is saved, and it never changes, never gets reused, and survives everything after that (renames, versions, deletes retire their number). Three decisions to make: 1) where the number comes from, 2) how it sits in the Project box on screen, 3) how the print's top-right corner carries it.

1 · Where the number comes from

pick one

The number must be unique across the team — two salespeople naming projects in the same minute can't both get N214. That rules the choice.

ApproachHow it worksTrade-offsVerdict
A · Postgres sequence A one-time SQL file adds a project_no column on the projects table and a database sequence starting at 100. Saving a project's name for the first time calls a tiny RPC that pulls the next number — the database guarantees no two projects ever share one. Needs one owner-run SQL file (same as every other migration here). Bullet-proof against two users colliding; the number is also searchable/sortable server-side later. Recommended
B · Highest + 1 in the app The number lives inside the project's saved data. On first name-save the app scans the loaded project list, takes the highest number, adds one. No SQL at all — ships today. But two users creating projects at the same moment can both compute N214; rare with a small team, not impossible. A repair pass could renumber duplicates on load, which breaks "the number never changes." Fallback
C · Year-prefixed Same machinery as A or B but the number reads N26-014 (year + counter that resets each January). Tells you at a glance how old a job is, but it's longer, harder to say over the phone, and the reset adds moving parts. You asked for N100 — noted only so it's consciously rejected. Rejected?

Also worth deciding now: do the projects that already exist get numbers? Two clean answers: backfill every existing named project in creation-date order (oldest = N100, the count today determines where new ones start), or fresh start — only projects named from launch day onward get numbers, old ones simply show none. Backfill feels right for a tracking number ("pull up N137" works on any job), fresh-start keeps the migration trivial. And the starting point: N100 rolls to four digits at N1000 and keeps counting — no padding, no ceiling.
