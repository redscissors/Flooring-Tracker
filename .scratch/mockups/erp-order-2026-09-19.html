ERP 1 order numbers — prototype

When a NED project is keyed into ERP 1, the order number ERP 1 hands you at the start goes into NED first. Until it's there, every line copy stays greyed out; once it's there, each line you copy is stamped with that order number, the green checks come back when the panel is reopened, and the number shows on the job and in the customer browser. A project split across two ERP orders keeps both numbers, and Copy remaining takes only the lines not yet keyed. Four things to pick: 1) where the number field sits in the panel, 2) how a split order reads, 3) how a stamped line shows its number, 4) the project header and the browser column.

All fixtures below are the preview harness's three-area job (Hendricks, N214) with two made-up ERP numbers, 48213 and 48260.

Reading the split. A line's stamp is a small moss tag on its SKU row, "✓ 48213". The active order's stamps and the other order's read the same — the chip row above already says which is active, and the tag is the answer to "which order did this go on".

Copy remaining replaces today's Copy all. It counts lines with no stamp on any order; copying stamps them all on the active order in one write. Copy selected copies whatever is checked, stamped or not, so a re-key on purpose is still one click — the check just moves to the active order.

Stock keyed lines show a checked, disabled box plus the tag — the same "done" look as the special lines' green check, in the control the row already has. Clicking the tag clears the stamp (with the same confirm as the special lines).

The footer keeps the existing rule: state only. "3 of 4 keyed · 2 on 48213, 1 on 48260" is state; the standing rules stay behind the ? on the heading.

Removing a chip that has stamped lines asks first: "Remove order 48213? Its 4 stamped lines go back to unkeyed." Removing an empty chip just removes it.

Option 2B — a dropdown instead of chips

One select listing the orders, plus "Add another…" at the bottom. Compact, but the whole point of the split is seeing both numbers at once and which lines went where; a closed select hides the second number. Better only if a project ever carries five or more orders, which nobody expects.

5 · What gets stored, and the rules

for the record

No SQL to run. Two new fields on the project's saved data, written through the same updateProject path as everything else, and one extra projected field in the boot's light rows so the browser can show and search the numbers without loading full projects.

project.erpOrders : [ { no: "48213", addedBy: "Marcus Mast", addedAt: 1758283920000 },
                      { no: "48260", addedBy: "Marcus Mast", addedAt: 1758303600000 } ]
                    // project order = added order; the LAST one is active when the panel opens

project.erpKeyed  : { "<line id>": { no: "48213", at: 1758284040000, by: "Marcus Mast" }, … }
                    // line id = the product row's id; a material line's "mat|Mortar|Mapei Ultraflex 2 gray";
                    // freight's "freight|<bookId>". A merged line stamps every source id it combined.
                    // Renaming a material product orphans its stamp — the line simply reads unkeyed again.

LIST_SELECT      += ", erp:data->erpOrders"      // the browser column + search, no migration
RuleBehaviour
Picks (owner 2026-09-19)1B header field left of the view switch · 2A chips (in that header row) · 3B number under the check / checkbox · 4A header chip · 4C browser column. Copy remaining replaces Copy all.
GateNo order on the project → every line copy, Ext, Copy remaining and Copy selected disabled (30%, tooltip). Deliver to never gated.
Active orderThe last-added chip, or the one clicked. Kept in the panel's own state — reopening the panel goes back to last-added.
StampCopying a line writes erpKeyed[id] = { no: active, at, by }. A merged line stamps each source. Copy remaining stamps its whole batch in one write; Copy selected the checked lines.
Copy remainingLines with a SKU and no stamp on any order. Count in the button label; disabled at zero with "Everything is keyed".
Clear a stampClick the green check (special) or the tag (stock) → confirm popover → delete the key. NED-only; says so.
Remove an order× on the chip. Confirm if it has stamps; removing deletes the order and its stamps. The next chip becomes active.
Same number twiceAdding a number already on the project selects that chip. Digits only, up to 10.
VersionsNot snapshotted. The stamp is about the live estimate; a restored version keeps whatever stamps still match its line ids.
PrintUntouched for now. Printing the ERP number on the order sheet is its own small ask.
