# Mirage floors quote by the square foot, not by the box

Reported 2026-07-27 against **86360** (Sweet Memories / Maple / Cotton Candy /
Character / TruBalance 5"): the row went by sq ft and no carton coverage could be
found for it.

## What was wrong

`parseMirage` emitted the canonical **SF/Carton** column as an empty string for
every floor:

```js
out.push([r.sku, floorName(r), r.collection, r.color, r.width, "", …])
//                                                            ^^ always blank
```

Downstream that is not a soft default — `stockPatch` only sets a row's
`cartonSf` when the item has `sfPerUnit > 0`, so with none the row can never
order in whole cartons. All 954 Mirage floors were affected, not just 86360.

The coverage does exist, and it is not in the chart: each flooring price sheet
closes its grid with a **Packaging** band stating box content once per
construction × width.

```
[ Packaging             |  | TruBalance 3/4" |        |        |       |       |
[                       |  | 5"              | 6-1/2" | 7-3/4" | 9"**  |       |
[                       |  |                 |        |        | Box A | Box B |
[ Box content (sq. ft.) |  | 22.70           | 14.75  | 23.00  | 25.45 | 19.00 |
```

Nothing read it, so the figure never reached the book.

## The fix

`parseMiragePackaging(sheets)` reads that band into a
`construction|width → sf` map, and `parseMirageFlooring` hangs the coverage on
each **price row**. That placement is the load-bearing part: the two sheets
disagree (TruBalance 7-3/4" is 23.00 sf on the 2026 Hardwood sheet and 17.60 on
the 2025 Value Tower), so a floor has to take coverage from the same sheet its
price came from, or it orders in a box the vendor isn't shipping. The join
already tracks which sheet won; coverage now rides along with the price.

**The 9" is left without coverage on purpose.** Mirage ships it as Box A (25.45
sf) and Box B (19.00 sf) in a 70/30 mix the sheet itself says "may vary from
order to order" — no single figure is true, and inventing one would round every
9" order to a box that doesn't exist. The parser reports the split and the import
warns; those rows keep quoting exact square feet. (Moot today: the current sheets
price 9" as N/A, so no priced floor lands there.)

Two warnings were added so a future sheet re-format can't quietly regress this:
floors reaching the book with no coverage are counted and their widths named, and
a split width is called out by name when floors actually land on it.

## Result

| | before | after |
|---|---|---|
| priced floors | 954 | 954 |
| with box coverage | 0 | 954 |
| 86360 SF/box | — | 22.70 |
| 86360 on a 420 sf job | 420 sf → $5,040.00 | 20 boxes (19.43 exact) → $5,448.00 |

Pricing is untouched — the sheet prices in $/SF, so `costSqft` still reads the
cost as-is and coverage only changes the quantity frame.

## Owner follow-up (live app)

   library). Coverage is written by the import; existing items don't gain it
   on their own.
2. **Re-pick 86360 on any open quote that already has it.** A picked row is a
   snapshot (ADR 0003) — re-importing the book does not reach back into saved
   estimates. Re-picking the SKU refills the row, or type `22.70` into the row's
   carton coverage box for an immediate fix without re-importing.
